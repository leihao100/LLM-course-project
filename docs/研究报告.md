# 不可靠病历下临床智能体的动作安全研究报告

本项目将两页计划书落实为可运行的研究框架、源码反例、实验协议和英文论文初稿。现阶段能够确认的是评分机制及执行抽象中的问题，尚不能确认任何大模型的故障发生率或缓解效果。离线演示来自明确标记的合成病例与编程基线；新增 CPU 模型与订阅推理实测见《双路径实测报告》。

## 研究问题与贡献边界

研究的核心是区分三件事：智能体是否忠实遵循当前病历；其动作是否符合预先声明的策略或干净参考；原评分器是否会接受该动作。三者可能同时出现分歧。例如，干净的镁值为 1.8 mg/dL，按基准规则应提出 1 g、1 小时的医嘱；将数值改为 0.18 后，同一规则会产生 4 g、4 小时的医嘱。如果评分器也读取 0.18，该错误参考可以接受 4 g 的动作。

这个例子支持“评分器可能接受由故障数据驱动的参考偏离”。它不证明真实模型一定会执行这种动作，也不等同于四倍临床伤害。本文所有剂量规则都来自 benchmark 的简化任务，而不是完整临床治疗方案。

建议将论文贡献表述为：共享病历状态导致的评分耦合；可观察证据缺陷与不可观察参考偏离的双重评价；独立参考与已提交动作的配对评分；证据核验提示的效益和正常任务成本。不要将“首个临床智能体评分器审计”作为贡献，因为已有直接相关工作。

## 已完成的源码核验

原仓库固定在提交 `99260117137b09f04837a8c18d18a1107efa55ae`。原始 `refsol.py` 从作者 README 指向的 Box 链接下载，SHA-1 为 `1440e8b982059a3fc730a26f448465f549910b36`，与公开页面记录一致。项目保存未修改的文件；审计运行时只替换网络读取，以便向原评分函数提供受控病历快照。

| 现象 | 实际复现 | 对计划书的影响 |
| --- | --- | --- |
| 评分器读取当前病历 | 同一条 4 g 医嘱在 0.18 病历上通过、在 1.8 病历上失败 | 支持评分耦合问题，属于确定性反例 |
| v1 的 POST 抽象 | 原 runner 解析 JSON 后返回成功，没有发送 HTTP POST | 原基准成绩表示接受的动作提案，不能称数据库已执行 |
| POST 子串检测 | “I will not POST an order”被识别为存在 POST | 是动作检测误差，通常造成错误拒分，不能说它产生了医嘱 |
| 最后一条消息越界 | 提及 POST 的末尾消息可使提取器抛出 IndexError | 评分器异常需独立保留，不能悄悄合并为普通失败 |
| 钾检验没有年龄限制 | 500 天前的 3.0 仍可按规则通过补钾及复查医嘱 | 原 task9 也没有时间窗，这属于规则选择，不是确定的实现缺陷 |
| 镁的未来日期 | 未来 30 天的记录仍满足原评分器的下界过滤 | 扩展策略明确拒绝未来证据，原评分结果保留作对照 |
| 缺失 HbA1c 的分支 | 原评分器要求新检验；任务明确要求返回 [-1]，但只明确为过期结果要求新检验 | 主策略采用任务字面解释，原评分结果作为语义敏感性对照 |
| route 格式冲突 | 工具定义给出对象 route，评分器要求裸字符串 IV | 属于格式问题，不能误写为剂量推理失败 |

上述结果保存在 `results/audit.json`。这些审计均未调用 LLM。公开原论文也说明 POST 仅作 JSON 检查，因此应将其称为基准执行抽象，而不是将没有真实写入作为新发现。

## 对原研究设计的必要修订

### 独立参考需要区分可观察与不可观察错误

当记录缺失、超出明确时窗、具有未知单位、来自未来或在同一时间互相矛盾时，智能体可以根据可见证据判断应当暂缓。当故障把一个值变成另一个仍合理的值，并且没有额外可信来源时，干净值对模型不可识别。仅要求其引用病历，不能恢复看不到的真值。

因此，分别报告“可观察策略违反”和“相对干净参考的动作偏离”。原计划的 `faithful_unsafe` 标签保留为研究策略下的标签，但其含义由这两个字段进一步解释。不能将所有参考偏离都归因于模型缺乏可实现的安全推理。

### HbA1c 的过期规则优先

如果当前可见的 HbA1c 已超过一年，任务明确要求新检验，不能因为干净病历中的结果较新，就将这次正确补查判为危险行为。框架允许这一任务特例，同时单独记录相对干净参考增加的检验。

缺失 HbA1c 时，主策略返回 [-1] 并暂缓。原始评分器要求新检验，两种语义并列保存，不混在一个正确率里。HbA1c 的数值和时间回答也被独立检查；医嘱正确不代表整个任务已完成。

### 单位故障的适用范围

0.4114 是本计划中镁的近似换算因子。将它乘到钾、血糖或 HbA1c 上并保持单位标签不变，不能统称为相同的单位换算错误。核心实验只在 task4、task5 的 mg/dL 镁记录上施加此故障。其他任务标为结构上不适用。源记录不是 mg/dL 时也应另记不适用。

### 模型比较减少家族混杂

原计划的 8B、32B、70B 很容易来自不同家族。默认改为同系列 Qwen2.5 Instruct 的 7B、32B、72B，统一 AWQ 4-bit 格式并锁定版本。仍须把结果解释为特定模型间的规模相关差异，而不是“只有参数规模发生变化”的因果实验。

### 干预与策略信息分开

两个实验臂获得相同的研究策略、检验时间窗和数字边界，拥有相同回合预算与工具。干预臂仅增加逐次写入前的检索、引用和核验流程。如果只告诉干预组策略要求，会把新增知识与流程效果混淆。

## 已交付的软件能力

框架只使用 Python 标准库，包含四种故障和干净对照、完整历史重选、不可变快照校验、每轮独立 SQLite 库、真实本地提交与读回、原评分器与独立评分器、模型端点客户端、严格配对的患者聚类 bootstrap、逐条运行文件和按配置恢复运行。

每条记录保存输入和策略哈希、故障前后对象、工具请求、已提交资源、回复、原评分结果、独立标签、时间与 token 用量。恢复运行的身份包含代码、完整配置和快照指纹；改变策略或代码会产生新的运行身份。错误后的已提交医嘱仍会接受安全评分，不能因 API 断开或没有 FINISH 就被忽略。

只读导出器支持 FHIR Bundle 翻页，并保存资源历史与校验文件。正式评估使用这些历史的本地缓存，并保留 benchmark 的简化资源表达，不能声称获得了真实 FHIR R4 服务上的执行结果。完整外部 EHR 写入及恢复适配器属于后续独立验证层。

## 当前验证结果

2026-11-05 的中期补充实验在同一份已授权两例输入上冻结新的统一格式协议：两提示臂均使用一致的 route 字符串 schema 和明确的 FINISH 回答形式。6 次新采样全部完成、全部通过原评分器，其中 2 次镁单位故障偏离独立干净参考；同一原始轨迹在干净病历下被原评分器拒绝。未修改剂量规则或评分器，也未事后规范化输出。这是先导机制证据，两个故障运行来自同一个镁病例。另对全部 30 条 Codex 轨迹移除数值边界进行重评分，4 条暂缓标签发生改变，不安全动作判定未变。54 项回归测试通过。详见《中期报告说明》及四页 NeurIPS 英文稿。

2026-10-31，用户明确授权的两例最小化原基准输入完成 6 次适用 Codex 运行，另外 2 次钾单位故障按预设标为不适用。4 次干净条件的医嘱符合独立参考；2 次镁单位故障中，普通提示和证据提示均提交 4 g/4 h，干净参考为 1 g/1 h。证据提示引用的数值、单位和时间与检索内容一致，故这一先导支持“引用当前记录不能揭示缺乏独立证据的隐蔽损坏”的具体机制，不能估计总体发生率或干预效果。

6 条轨迹的原评分均未通过，全部存在 route 对象与原评分器要求裸字符串的冲突，最终回复也不符合其数值列表或空列表约束。原始结果没有经过格式修正，不能把独立评分的 4 次正确当作原评分器通过。详细记录、25 个推理回合的使用量、授权范围和每轮恢复校验见《双路径实测报告》及 `results/pilot-original-codex/verification.json`。本次报告检查不替代预定双人盲审。

已完成源码反例及自动测试，覆盖剂量边界、时间窗边界、单位归一、未知单位、并发冲突、有效替代记录、重复医嘱、错误患者、警告后仍写入、提交后中断、配对缺失、患者聚类、校验文件和模型 HTTP 请求协议。最终测试数量及日志见交付根目录的验证记录。

合成演示使用 30 个病例，3 个编程控制策略，5 个条件。450 个名义组合中 54 个不适用，396 个有效运行。它检验软件路径，不为真实临床记录或大模型提供性能证据。

选出的真实任务各类别 30 个，共 150 个任务，涉及 87 位患者。两个用药类别合计 60 个任务，涉及 54 位患者。这是任务清单的直接统计，不是运行过真实病历后的结果。

## 仍需真实资源完成的工作

首先启动原 MedAgentBench 镜像，记录镜像摘要，导出完整的基准病历，检查单位、时间、缺失分支和原始参考是否可解释。随后使用原 harness、全部 300 个任务进行独立的历史结果复现；原论文 GPT-4o-mini 的总体成功率为 56.33%，这个数字不能直接用于 150 个任务子集或扩展 harness。[MedAgentBench 原论文](https://arxiv.org/html/2501.14654v2)

在真实快照通过预检后，以小规模先导实验测量上下文长度、回合数、推理速度和无效格式比例，再完成三模型、两实验臂的主体实验。对异常解释进行双人盲审，对没有数值边界的策略重新评分或重跑，并将统计结果填入论文的预先定义表格。

目前已取得全部 150 个任务的相关病历快照，部署 CPU 小模型并完成有限的订阅推理测试；主体三模型实验、临床领域策略审阅和人工解释标注仍待完成。因此论文具备审计、数据剖析与先导实验初稿，尚不能作为已完成主体模型比较的实证论文提交。
